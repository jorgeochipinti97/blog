I didn't know how to solder. I didn't know what a breadboard rail was. I ended the session with a working shopping kiosk — Claude as the brain, a reactive full-screen avatar, real store data.

Here's what I built and how it works.

## The hardware

The Keyestudio "Xiaozhi" kit comes with an ESP32-S3, an INMP441 microphone (I2S), a MAX98357A amplifier with speaker, and an LCD screen. It came pre-flashed — I didn't write a single line of C++.

I assembled everything on a breadboard. First problem: an invisible bad contact on the microphone. The firmware ran fine, but the mic captured nothing. Fix: reposition the module, unplug and replug so the I2S reinitializes. No sophisticated debugging. Just physics.

## The architecture

```
[ Person speaks ]
      │ mic I2S
      ▼
   ESP32-S3  ──WebSocket──►  Docker server (Mac)
                               VAD → STT → LLM → TTS
             ◄──────────────  audio response
                                    │ docker logs -f
                                    ▼
                           SSE bridge (Next.js)
                                    │
                                    ▼
                           Full-screen kiosk (Next.js)
                           face + store cards
```

The ESP32 does one thing: capture voice and play audio back. The brain runs in a Docker server on the Mac. The avatar is a separate Next.js app.

That last decision was the most important one in the project.

## The brain and the screen

**Voice stack:**
- **VAD:** SileroVAD (local)
- **STT:** OpenAI Whisper (`gpt-4o-mini-transcribe`) — the local STT doesn't support Spanish
- **LLM:** Claude `claude-haiku-4-5` via Anthropic's OpenAI-compatible endpoint
- **TTS:** OpenAI `tts-1`, voice `nova`, speed 1.2

One problem that took a while to understand: Claude was responding in Chinese. The firmware's default prompt was in Mandarin, and the Spanish voice can't read Chinese. Switching the prompt to Spanish fixed the language and the TTS at the same time.

**The avatar (Next.js + Tailwind v4 + framer-motion):**
A face with eyes and mouth, 4 states: idle, listening, thinking, speaking. Spring animations so no transition ever looks abrupt. The state doesn't come from the server — it comes from parsing Docker logs in real time, via SSE.

When Claude recommends a store, the avatar shows its card: real logo, real photo, floor number, and category. Up to 3 cards, with a staggered entrance animation.

## The real case: Toscas Shopping

This wasn't a demo. The `toscas` persona knows all **91 real stores** in Toscas Shopping (name, category, photo, logo, floor). I scraped them with `curl` because the website blocked normal scrapers. The categories were generic (Clothing = apparel + footwear + lingerie), so I researched each store with 5 parallel agents and added subcategory, products, and gender tags. That lets Claude recommend precisely: "sneakers" goes to footwear, not home goods.

The assistant greets, asks what the person is looking for, recommends with floor number, and wraps up.

## What I learned

The LCD on the ESP32 wasn't viable without recompiling the firmware in C++. The large external screen (web full-screen) gave me full control, fast iteration, and is the real front of the kiosk in production.

Latency is dominated by the STT → LLM → TTS chain, not the hardware. With all three via API it runs around 2-3 seconds.
